# Independent review of the micro-LF FPGA project

Review date: 9 November 2026. Documentation baseline: [`perkusic/lingua-franca-docs` on GitHub, `cf90b9e8ca64ee976cbf17e47d5ce84df632cbb4`, 9 November 2026](https://github.com/perkusic/lingua-franca-docs/tree/cf90b9e8ca64ee976cbf17e47d5ce84df632cbb4). The project definition export is present; findings refer to that snapshot, not to the live document or its interactive diagrams.

**Verdict.** The original uLF source fails validation because `tardy` is reserved. The hand-written C is an experimental reference, not an exact copy of generated code. The runtime acquisition rule is close to the description once it is limited to connected inputs and distinguished from the scheduler's physical-time wait. Two notable corrections are that late-event delivery is a retry, not a guarantee, and an event-queue insertion failure in the dynamic scheduler terminates the process instead of logging a recoverable drop. The project can proceed with a Linux baseline; OQ-7 still requires an application-specific argument and the board gates need measurable criteria.

### Why tag 500 can resolve after the sensors stop

The pinned POSIX path permits a fourth outcome beyond receiving a value, receiving a stop message, or timing out: **TCP disconnect wakes the waiter and removes that bundle from the acquisition scan.** No B data at tag 600 is scheduled with a 550 ms logical stop, and the nominal tag-500 deadline for W = 100 ms is 600 ms, not 550 ms. EOF moves the TCP channel out of CONNECTED and invokes `notify`; an interrupted scheduler wait restarts, then `acquire_tag` skips the closed channel. This can release tag 500 with A present and B absent without changing B's knowledge frontier. The configured timeout is a logical stop tag, not a wall-clock kill at 550 ms. The scheduler acquires pending data tags and also acquires the shutdown tag.

Evidence at the revision in Section 1: [`src/platform/posix/tcp_ip_channel.c`, connection transition and notification](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/platform/posix/tcp_ip_channel.c#L42-L53), [EOF](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/platform/posix/tcp_ip_channel.c#L342-L363), [`src/environments/federated_environment.c`, acquisition](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/environments/federated_environment.c#L89-L121), and [`src/schedulers/dynamic/scheduler.c`, stop and retry](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L332-L403).

**Observed in the debug V3 run:** `trace/V3-1/fusion.log` lines 1071–1107 show B unresolved at tag 500, an interruptible wait for the absolute tag-600 deadline, `CONNECTED => CLOSED`, platform notification, interrupted acquisition, and execution of tag `(500 ms, 0)` with only A at lag **50.445 ms** (physical elapsed time **550.445 ms**). It is the connection-state wakeup, not a B value, a shutdown message, or the expiration of the tag-500 deadline. The timed run, without DEBUG, measured **50.559 ms**.

**Generated V3:** `generated/V3-1/sb.log` records environment teardown about **450.223 ms** after the agreed start. B sends its last value at tag 450; the next timer event is after stop and is rejected. With keep-alive false, the scheduler can exit when its ordinary queue empties, close the socket, and leave B out of the later tag-500 scan. Fusion observes the disconnect before tag 500, which runs at lag **0.198 ms** with the same presence and sums. See [`src/schedulers/dynamic/scheduler.c:267–278`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L267-L278) and [391–403](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L391-L403), at the runtime revision in Section 1.

## 4 Task 3 Runtime claims

All runtime links are to **`lf-lang/reactor-uc` on GitHub, commit `df7cfeae7083509621b8f5080c066051112e2500`, 7 September 2026**. File names and source spans refer to this revision.

1. **PARTLY — release at known tag or maximum wait.** The dynamic scheduler first selects a candidate and waits for its time, except when a mode such as fast execution bypasses sleeping. `acquire_tag` considers only connected bundles, locks each connection while reading knowledge, and takes the maximum positive `max_wait` among unresolved inputs. It waits until `lf_time_add(g.time,W)`; zero returns immediately, `FOREVER` remains a sentinel, and an interrupted sleep restarts candidate selection. It does not require knowledge on disconnected channels or guarantee execution at the exact deadline. [`src/environments/federated_environment.c:41–61`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/environments/federated_environment.c#L41-L61), [89–121](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/environments/federated_environment.c#L89-L121), [`src/schedulers/dynamic/scheduler.c:341–385`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L341-L385), [`src/tag.c:13–26`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/tag.c#L13-L26).
2. **WRONG as a runtime API claim — KNOWN and EXPIRED are not distinct return values.** These are useful proposed diagnostic labels. The no-wait path and an elapsed/successful timed wait both return `LF_OK`; POSIX timeout returns `LF_OK`, notification yields `LF_SLEEP_INTERRUPTED`. A monitor must instrument the decision rather than infer it from the result. Zero wait, disconnection and fast mode also need an explicit classification. [`src/environments/federated_environment.c:41–61`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/environments/federated_environment.c#L41-L61), [113–121](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/environments/federated_environment.c#L113-L121), [`src/platform/posix/posix.c:41–67`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/platform/posix/posix.c#L41-L67).
3. **PARTLY — tardy retry with value, conditional on success.** Stop-tag rejection precedes the past-tag check. A past-tag rejection retries at the receiver's *current logical tag* with its microstep incremented; that time need not equal the incoming message's time. The initialized `intended_tag` and allocated value are retained. A failed retry can drop the event; a reaction with the appropriate handler dispatches it when the present input's intended tag differs. [`src/federated.c:205–250`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/federated.c#L205-L250), [`include/reactor-uc/event.h:9–13`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/include/reactor-uc/event.h#L9-L13), [`src/schedulers/dynamic/scheduler.c:155–215`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L155-L215), [409–439](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L409-L439).
4. **CONFIRMED for the runtime predicate, conditional for absence inference.** Reception raises `last_known_tag` to the adjusted tag if larger after successful pool allocation; a later frontier satisfies acquisition for earlier candidates on that connection. Successful insertion notifies the waiter. Interpreting the frontier as evidence of absence assumes monotone sends, ordered/lossless admission and no defect path. In V3 the nominal 50 ms pattern follows the next sensor firing, for example B150 resolving B at tag 100. [`src/federated.c:189–259`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/federated.c#L189-L259), [`src/schedulers/dynamic/scheduler.c:436–444`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L436-L444).
5. **CONFIRMED with scope.** 832 is the bounded `TaggedMessage` payload in bytes, not the entire encoded envelope or an AXI frame size. `Platform` has the five stated callbacks; mutex lock/unlock and platform creation are separate contracts, not a sixth callback. A port must also implement initialization and interrupt-safe behavior. [`external/proto/message.proto:10–15`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/external/proto/message.proto#L10-L15), [`include/reactor-uc/serialization.h:8–15`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/include/reactor-uc/serialization.h#L8-L15), [`include/reactor-uc/platform.h:18–58`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/include/reactor-uc/platform.h#L18-L58).
6. **PARTLY — three candidate upstream issues.** (a) Allocation failure leaves knowledge unchanged. Deserialization failure, invalid/after-stop rejection and a nonfatal retry failure after allocation can raise it without admitting the event. Queue insertion failure in the dynamic scheduler instead hits always-on `validate` and exits; its nominal `LF_VALUE_BUFFER_FULL` handling is not a recoverable path in this scheduler. (b) Those nonfatal drop paths have no payload release in the receive callback. A normal admitted input releases its slot on preparation. (c) The joining announcement loops over `j` but writes `inputs[i]`, using the bundle index, without that connection's lock or a monotonicity guard. It may update the wrong input, lower knowledge, or index beyond the array. These are code findings, not failure-injection reproductions; no upstream issue was filed and no runtime code was modified. [`src/federated.c:128–151`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/federated.c#L128-L151), [207–259](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/federated.c#L207-L259), [`src/schedulers/dynamic/scheduler.c:436–444`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/schedulers/dynamic/scheduler.c#L436-L444), [`include/reactor-uc/error.h:27–38`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/include/reactor-uc/error.h#L27-L38), [`src/startup_coordinator.c:492–510`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/startup_coordinator.c#L492-L510).

## 5 Task 4 Project definition and consistency findings

All MR-01 through MR-12 name existing tests; all D-1 through D-7 appear in the stated P0 through P5 phase exits. Those links establish traceability, not adequacy. The five interactive diagrams are placeholders in the export. The following replacement text is proposed for the owner to apply to the live definition; the export is unchanged.

### High severity

**B1 — Observed waiting threshold does not settle OQ-7.** Summary: “The measured answer is the input to open question [OQ-7]” and motivation: “a small measured W shows that decentralized coordination suffices for a defined class of on-chip federations.” [OQ-7 in the specification](https://perkusic.github.io/lingua-franca-docs/hw-rti/HW-RTI_project_specification.html#tab-open-questions) explicitly calls for an argument from target applications, before M-4; [R-9](https://perkusic.github.io/lingua-franca-docs/hw-rti/HW-RTI_project_specification.html#tab-risks) limits the evaluation claim. [DEC-13](https://perkusic.github.io/lingua-franca-docs/program/implementation_guide.html#dec-13) makes measurements evidence for that argument. **Replace:** “Before M-4, use the B1 and B2 measurements as evidence in an application-level OQ-7 argument. Specify the topology, enforceable timing bounds, and response to missing or tardy input. A finite sweep identifies a successful tested configuration, not a worst-case safety bound.”

**B2 — Common oscillator is not a complete timing argument.** “On one chip there is a single oscillator, so the clock error between federates is zero,” and “a dedicated FIFO or a time-divided network-on-chip bounds L.” [DEC-10](https://perkusic.github.io/lingua-franca-docs/program/implementation_guide.html#dec-10) actually proposes a common counter; a FIFO alone does not bound waiting for service or backpressure. A bare-metal sender still incurs scheduler, interrupt, memory and transport delay. **Replace:** “Use one coherently sampled fabric counter to remove independent clock drift. Bound timestamp sampling and conversion error. Derive the channel delay bound from the service schedule, finite traffic assumptions and backpressure policy; include sender and receiver scheduling in the end-to-end budget.”

**B3 — MR-10 claims identical traces beyond its assumptions.** “Logical traces are identical across repeated runs, across channels and across platforms, for programs whose inputs do not come from physical actions.” Finite waiting can change presence and tardiness even if all tags come from logical timers. T-2 compares the two channels but does not explicitly compare platforms and repeat trials. **Replace:** “For the declared workload and timing envelope with no tardiness, compare logical tag, presence and value traces across repeated runs and supported platforms. For a bounded wait that can expire, compare each run to the policy oracle and retain the violation trace.” Extend T-2 to both platforms and report all repeats.

**B4 — PASS does not prove expected tardiness.** “PASS means 8 reactions and correct sums (a = 21, b = 10), and the tardy count expected for the run.” The shutdown predicate does not test tardy count. A normal reaction count of eight is also not the total number of invocations in V2. “A late message is not lost” overstates the retry guarantee. **Replace:** “The shutdown line checks eight ordinary reactions and sums a = 21, b = 10. The test harness separately checks the expected presence trace, tardy count and microstep, and all process exits. In the V2 trace the late value is recovered by a successful retry.”

### Medium severity

**B5 — Gates and exit evidence are underspecified.** “P3 and P4 are each started only if their gate passes” and “six phases, three gates.” G1 is not defined in the export, and G2/G3 lack measurable pass criteria; P5 exit “D-7” is a name rather than an acceptance test. **Insert before objectives first use a gate:** “G1: allow fabric measurements after T-1/T-5 and an archived B-TCP trace. G2: approve the soft-core phase only after a selected core, toolchain, memory budget, channel adapter and timing hypothesis are documented. G3: approve offload only when a predeclared admission-latency or CPU-cost threshold is exceeded and a reference model and verification budget exist.” State exact numeric thresholds with the owners before using the gates. For P2/P4 explicitly require applicable T-7 clean rebuild and post-route evidence; for P5 require a report with trace links, exclusions and disposition of each candidate upstream issue.

**B6 — Timestamp and instrumentation tests leave gaps.** MR-06: “Each federate logs, per message: arrival, admission, the decision (KNOWN … or EXPIRED …), reaction start, and tardy events, timestamped with the fabric counter.” A candidate can expire without any message, and P1 requires T-5 before the fabric time base exists. T-4’s “monotonic and identical across federates” is not meaningful for unsynchronized samples at different times. **Replace:** “Record message arrival/admission and separate candidate decisions with epoch, tag and physical clock source; record execution and tardiness as separate events. Use the host clock in P1 and the fabric counter in P2. Test coherent multiword reads, rollover, clock scale/epoch and wait/notify deadlines, including boundary arrivals, disconnect and reset.” Define diagnostic states in the instrumentation rather than claiming runtime enum values.

**B7 — Generated code compatibility and FIFO losslessness need contracts.** “Nothing in the generated code changes: the channel and the time source are selected when the federate is built” and MR-02 “ordered, lossless.” The generated bundles instantiate concrete TCP types and constructors. A custom channel needs a supported generation/configuration route or a compatible adapter; selecting a CMake option alone is not evidence. MR-03 allows timeout failure; the existing sender logs `send_blocking` failure without making delivery reliable. **Replace:** “The LF application remains unchanged. Demonstrate that the selected generator or adapter configures the channel without manual edits to generated files. Preserve ordering and exactly-once admission for successfully enqueued frames within an epoch; specify the observable outcome of timeout and reset.” Add to T-2/T-3 a generated build, frame-limit test (832 payload bytes plus framing), and a peer-observed failure/epoch trace. Runtime evidence: [`src/federated.c:18–50`](https://github.com/lf-lang/reactor-uc/blob/df7cfeae7083509621b8f5080c066051112e2500/src/federated.c#L18-L50), at the commit in Section 1.
