How to use this guide. It is the single place where implementation decisions are recorded, ordered and justified. Requirements stay in the HW-RTI specification, which remains normative; explorations stay in the design notes; background stays in the tutorial. Each decision has an identifier (DEC-nn), a status — decided, proposed or open — its basis, and the documents that carry it. A change of decision is made here first and then propagated to the documents listed. This guide replaces the program overview of 7 October 2026.
§ 1

Where the project stands

The Phase 1 platform is the AMD ZCU106 (Zynq UltraScale+ XCZU7EV, four Cortex-A53 cores and two Cortex-R5F cores next to the programmable logic). A port of reactor-chisel and the Codesign flow is reported to work on that board; this guide takes it as given but has not audited it. HW-RTI is specified and not yet implemented. Two tracks share the hardware: Track A, the centralized HW-RTI, is specified; Track B, decentralized coordination with micro-LF and possibly a hardware input engine, is exploratory. Both answer the same question — when may a participant commit to a tag — with different evidence: logical evidence collected by a coordinator, or local knowledge plus timing bounds (tutorial §5 and §5.3).

§ 3

Plan: stages and gates

One sequence covers both tracks. Each stage has an acceptance gate; a stage starts only when the gates it depends on have passed. The P-stages follow the specification’s milestones and add the first board federation (P4) as an early, restricted slice of M-5, so that the board, the adapter and the participant interface are exercised before the full decision core exists. The B-stages produce the measurements that OQ-7 needs before M-4 and then reuse the participant infrastructure of P3–P4.

§ 4

The reactor-chisel boundary

At reactor-chisel d94dd2d the coordination interface of the TriggerGenerator cannot be driven directly by HW-RTI. The three incompatibilities below were confirmed in source on 8 October 2026 and are now recorded in the specification (§8.1, FR-20, D-11, OQ-8).

Table 4 — the reactor-chisel boundary at d94dd2d.
PropertyAt d94dd2dAdapter behaviour (FR-20)
Tag representation32-bit unsigned scalar of nanoseconds, no microstep (Tag.scala). NEVER = Int.MinValue as unsigned compares above FOREVER = Int.MaxValue. Range about 2.1 s.Convert in both directions with microstep 0 towards the core; map sentinels explicitly; compare only in the core encoding; FR-18 error outside the range or when a microstep other than 0 is needed. The hardware clock counts from the start of execution, so the conversion is relative to the federation start tag (spec §8.2 START_TAG); confirm against the Codesign wrapper at P1.
Grants above NETThe scheduler asserts “TAG > NET not allowed yet” except for FOREVER (Scheduler.scala, line 48).Retain the granted TAG and present min(TAG, NET), re-presenting as NET advances; unless DEC-05 removes the assertion.
Provisional grantsCoordinationIO has no PTAG input.Forward no PTAG; reject at topology load a hardware federate in a zero-delay cycle.

The ZCU106 note lists further adapter obligations that the participant interface of P3 must meet: separate grant value, validity and acknowledgement from input publication (the original WRITE couples them); a command handshake that cannot lose repeated commands; a READ-equivalent consumption acknowledgement; a participant NET that combines admitted external events, timers and physical actions rather than the local token queue alone; and LTC only after reaction work and outbound commitments are complete (FR-19). reactionDone defaults to true and must be driven for multi-cycle reactions.

§ 5

Contracts

These outlines become frozen formats at P3; the specification is normative wherever it already defines a field.

  • Tag. Spec §6.1: (SInt64 nanoseconds, UInt32 microstep), NEVER_TAG and FOREVER_TAG as defined there. The reactor-chisel mapping of §4 is the only other encoding.
  • Progress and grant record. Spec §8.1 ControlMsg and Grant: participant, kind, tag; NET, LTC, MSG_SENT, RESIGN and stop messages inbound; TAG, PTAG, DNET and stop grants outbound. Grant permission and progress frontier keep distinct meanings; validity is separate from sentinel values.
  • Event record. Destination connection, intended tag, presence, payload handle and length, sequence number and epoch. The intended tag is kept even when an event is admitted late (reactor-uc keeps intended_tag for the same reason).
  • Trace record. Spec FR-17 trace port, extended for the board: physical timestamp, participant, event tag, and the distinct points of candidate query, commit, execution, completion, transport commit and violation.
  • Topology manifest. Participant and connection identifiers, logical or physical type, delay, payload schema; the same manifest drives both policies.

Compare logical traces against a reference transition model, not clock-cycle timing between policies. Where finite waiting changes behaviour on purpose, judge each trace against its own declared contract and report the violations. Measure event-to-execution latency, physical lag, coordination traffic, queue occupancy, wait time, tardy count, throughput, logic and RAM use, and timing closure, with identical reactions, topology and channel capacity for both policies.

§ 7

Open questions

  • Matched sources (DEC-11): which reactor-chisel and LF-fork commits does the working ZCU106 port use? The submodule commit 6c8aecd and the runtime baseline d94dd2d differ.
  • Widening reactor-chisel (DEC-05, spec OQ-8): needed if the target application requires microsteps, runs longer than about 2.1 s of logical time, or needs zero-delay cycles through hardware federates.
  • Software side of Codesign. The Codesign wrapper targets the C++ runtime (ZCU106 note, citing CodesignSwEmitter.kt), while the specification’s software federates (configuration C-B) run the C runtime. Decide which runtime the A53 federates use in P5–P6.
  • Distribution (DEC-13, spec OQ-7): answered before M-4.
  • Upstream reports (DEC-14): the reactor-uc joining-time write and the knowledge advance after a dropped event; the reactor-chisel sentinel order.
  • reactor-uc startup on cyclic topologies: whether the two-sweep round count reaches the diameter.
